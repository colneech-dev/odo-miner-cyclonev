### Confirmed RTL bugs

**BUG-1 — STATUS.EPOCH_LOCK always reads 0**

```verilog
// odocrypt_top.v:212 — WRONG
avs_readdata = {28'h0, STAT_EPOCH_LOCK, 1'b1, found_latched, core_busy};
// STAT_EPOCH_LOCK = 1u<<3 = 32-bit constant → concat is 63 bits wide
// after 32-bit truncation, bit 3 of readdata is 0, not 1
```

Correct form:
```verilog
avs_readdata = {28'h0, 1'b1, 1'b1, found_latched, core_busy};
//                      ^         ^
//                 EPOCH_LOCK  CORE_READY
```

**BUG-2 — `busy` multi-driver in `odocrypt_core.v`**

`busy` is `output reg` and is assigned in BOTH the `always @(posedge clk)` reset
branch AND `always @(*)`. Multiple-driver violation. Remove `busy <= 1'b0` from
the sequential block; drive only from combinatorial.

**BUG-3 — `odocrypt_array.v` header_words width mismatch**

Array module declares `[0:23]` (24 words). Core expects `[0:19]` (20 words).
Port-width mismatch, will error at synthesis. Fix: change array to `[0:19]`.

**BUG-4 — `core_start_pulse` is a one-cycle combinatorial glitch**

Generated directly from `avs_write`. If core is busy when HPS writes START,
the pulse is dropped and the job never launches. Need either a start-pending
latch or a HPS convention to check BUSY=0 first.

**BUG-5/6 — `hdl/src/hps/miner_daemon.c` and `stratum.c` are stale and broken**

Reference non-existent `fpga_regs.h`, use API names that don't match the
canonical `hps_regs.h` and `stratum.h`. These files should be deleted; `hps/`
is the canonical source tree. The `hps/stratum.c` also has a callback-based
internal API (`ctx->on_job`, `ctx->cb_arg`) that does not match the
`stratum_ctx_t` struct in `stratum.h`.

**BUG-7 — `cdc_bus.v` ready signal unsynced across clock domains**

`assign ready_src = ready_dst` — direct cross-domain connection. Benign now
(single clock), will be a metastability source once the PLL hash clock is added.

### Algorithm correctness (updated 2026-05-31 after reading upstream)

**The real OdoCrypt pipeline is:**

```
80-byte block header (640 bits)
  ↓  odo_encrypt  (84 rounds per epoch-keyed tables)
640-bit midstate
  ↓  Keccak-800
256-bit PoW hash
  ↓  compare ≤ target
```

**The real odo_encrypt round structure (84 rounds):**
1. `Pbox0`: 6 subrounds of masked-bit-swap → word-shuffle(×3) → rotation-of-even-words
2. `Sbox`: for each 64-bit word, process as 4 × (6-bit small sbox + 10-bit large sbox)
3. `Pbox1`: same structure as Pbox0 with independent epoch-derived tables
4. `Rotations`: rotate word array by 1; XOR each word with 6 rotations of the original
5. `RoundKey`: XOR state[i] with bit i of the 10-bit round key integer

**Epoch table sizes:**
- 40 small S-boxes: 40 × 64 × 1 byte = 2.5 KB
- 10 large S-boxes: 10 × 1024 × 2 bytes = 20 KB
- 2 P-boxes: masks (6 × 5 × 8 bytes) + rotations (5 × 5 × 4 bytes) each ≈ 340 bytes per box
- 6 global rotations + 84 round keys: trivial

**The epoch tables are generated by the `OdoRandom` LCG:**
- Non-standard: each NextInt() call updates both `multiplicand` and `addend`
- `addend += multiplicand * LCG_ADD; multiplicand *= LCG_MUL; current = current * mult + add`
- This ensures every seed produces a unique sequence (not just a phase shift)

**Strategy for standalone miner:**
- The HPS runs the LCG (C code in `hps/odocrypt_state.c`) to generate all epoch tables
- HPS loads the tables into FPGA BRAM via MMIO on epoch change
- FPGA uses the BRAM contents in the pipeline — no LCG hardware needed
- `odo_encrypt` result feeds into Keccak-800 (upstream `keccak800.v`) before target compare

**RTL redesign required:**
1. Replace `odocrypt_epoch_mutator.v` with S-box and P-box BRAM write interface
2. Rewrite `odocrypt_round.v` to implement Pbox→Sbox→Pbox→Rotations→RoundKey
3. Add Keccak-800 stage after the 84-round pipeline (port `upstream/odo-miner/src/verilog/keccak800.v`)
4. Register map extension for BRAM write port and epoch load strobe

**`hps/odocrypt_state.c` is now implemented** — faithful C port of `odocrypt.cpp`.
It generates all epoch tables and implements `odo_encrypt()` as a software reference.

### Performance counter note

`perf_hashes_lo/hi` in `odocrypt_top.v` increments on `core_busy`, not
`core_hash_valid`. It counts busy clock cycles, not completed hashes. Should
be fixed to increment on `core_hash_valid` for accurate hash-rate telemetry.

---

### Pipeline timing note

`odocrypt_compress.v` registers `in_state` at stage 0, adding one extra
register relative to what the core's `pipe_nonce` shift tracks. Whether
`pipe_nonce[PIPE_DEPTH]` correctly identifies the winning nonce needs
verification in simulation. See TODO ALGO-4.

### Current hardware status

- HPS Linux: `/dev/mem` opens and mmap succeeds at `0xFF200000`.
- Smoke test: all registers read `0xFFFFFFFF` — expected, because no bitstream
  exists yet. An unconfigured FPGA fabric floats high over LWH2F.
- `hdl/quartus/` and `hdl/qsys/` are empty — no Quartus project or Platform
  Designer system in the repo. This is the primary blocker.
- `0xFF200000` is the LWH2F base fixed by Cyclone V SoC architecture, not by
  the Quartus project. What the Qsys project sets is the miner slave's offset
  within that window. `hps_regs.h` assumes offset 0x0; the Qsys assignment must
  match.
- **Bridge enable is a separate required step.** After loading the bitstream,
  the LWH2F bridge must be explicitly enabled (sysfs `fpga-bridge` or U-Boot
  `bridge enable`). Skipping this also returns `0xFFFFFFFF`. Must be part of
  every bring-up and reconfiguration sequence.
- Next hardware step: create Quartus/Qsys project → synthesise → load `.rbf` →
  enable bridge → re-run smoke test.

### Multi-core engine sketch

Replace single-core with:
```verilog
odocrypt_array #(.CORES(4)) corefarm_inst (...)
```
Nonce range is striped across cores at stride CORES.

### Stratum submit function skeleton

```c
int stratum_submit_share(const char *user, const char *worker,
                         const char *job_id, const char *extranonce2,
                         const char *ntime, const char *nonce_hex);
```
Nonce should be 8-char hex. Little-endian vs big-endian depends on pool;
most pools expect big-endian representation of the nonce field.

### OdoCrypt epoch mutation model (approximate — not real algorithm)

The real OdoCrypt mutation is Keccak-800-based, seeded from epoch number.
See `upstream/odo-miner/src/crypto/odocrypt.cpp` for the authoritative
C++ implementation before writing any RTL.

### Block header layout (80 bytes → 20 words)

| Byte offset | Field | Notes |
|-------------|-------|-------|
| 0–3 | version | 4 bytes LE |
| 4–35 | prevhash | 32 bytes |
| 36–67 | merkle_root | 32 bytes |
| 68–71 | ntime | 4 bytes LE |
| 72–75 | nbits | 4 bytes LE |
| 76–79 | nonce | filled by FPGA; zero in header template |

### Reset strategy for PLL

```verilog
reg hash_reset_n;
always @(posedge clk_hash or negedge pll_locked) begin
    if (!pll_locked) hash_reset_n <= 1'b0;
    else             hash_reset_n <= 1'b1;
end
```
