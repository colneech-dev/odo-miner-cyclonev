Design Review · June 2026

odo-miner front‑end & web dashboard

A critique of the appliance's two user-facing surfaces — the LAN web dashboard served by odo-webd and the on-device 2.8″ TFT touch panel driven by odo-ui. Both are competent, function-first engineer UIs. What follows is a polish pass, not a rebuild.

01

Web dashboard

odo-webd · :80 · trusted LAN

A single self-contained page, auto-refreshing every 3 s, with status cards plus pool & WiFi configuration forms. Recreated below from the served markup with live-looking data.

As served — mobile, full scroll
W1
Critical · Brand
Borrowed identity
The shield-and-slash mark and navy/blue palette are lifted from Miningcore — the source comments say so outright (“miningcore-inspired palette”, “rendition of the Miningcore shield”). Shipping another project's logo and colors is an IP and credibility risk. Commission an original mark and a palette you own.
W2
Issue · IA
Monitoring & config share one scroll
Five equal-weight cards stack glance-data and three destructive config forms in one column. A quick “is it mining?” check scrolls past payout-address and reboot controls. Split Status from Settings — tabs, or a collapsed config drawer.
W3
Issue · Feedback
No confirmation after saving
Saving pool or WiFi config just 303-redirects to /. The user gets no “Saved — miner restarting” state, so it's unclear the action landed. Add an inline success / now-restarting banner.
W4
Issue · Type
Live numbers jitter
Hashrate, shares and uptime refresh every 3 s in a proportional font with no tabular figures, so digit widths shift and the layout twitches. Set font-variant-numeric: tabular-nums on every live value.
W5
Issue · Hierarchy
Flat visual rhythm
Every card is the same navy rectangle, so the hero hashrate reads no louder than the WiFi form. Give the status/hashrate card more weight — size, an accent edge — and let the config cards recede.
W6
Issue · Action
Adjacent same-weight buttons
“Save & restart”, “Restart miner” and the red “Reboot board” sit in one run; the two blue restart-ish buttons are easy to confuse. Separate by spacing and a secondary (outline) style for the lesser action.
W7
Issue · Forms
Long address in a short field
The worker / payout field holds a 34-char address on one line in a proportional font — it truncates with no wrap. Make it full-width, monospace and selectable so users can verify it at a glance.
W8
Strength
Defensive status model
Stale-detection (“MINER DOWN” when the snapshot is >120 s old), connected/offline chips, and confirm() guards on every destructive action are genuinely well handled.
W9
Strength
Right-sized for the job
Zero-dependency single page, mobile-first 560 px column, 3-second refresh — exactly the right footprint for a trusted-LAN appliance. Resist the urge to over-engineer it into an SPA.

Companion screens not shown: a full on-screen WiFi keyboard, a network scan list, and boot splash — all in the same language.
1
Critical · Brand
Same borrowed mark & palette
Cross-surface consistency with the web UI is the right instinct — but the shared asset is the Miningcore shield and colors. Fix the identity once and it propagates to both surfaces.
2
Strength · Layout
Excellent use of 320×240
Header, a hero hashrate in cyan, a two-column stat grid and a three-button action row — a lot of legible structure packed into a 2.8″ panel. The hierarchy is clearer here than on the web.
3
Issue · Density
Past the comfort line
Hero + pool + six stat rows + three buttons at an 8 px bitmap font is hard to read at arm's length on a low-contrast TFT. Promote 2–3 vital stats (hashrate, pool OK, last share); push the rest to a second screen.
4
Issue · Robustness
No truncation on variable fields
The pool value starts at x=58 and the right column at x=168; a longer host runs straight into the JOB / UPTIME column. Same risk on SSID and epoch. Clip or ellipsize fixed-width fields.
5
Issue · Touch
Tight keyboard targets
The action buttons (~34 px) are fine, but the WiFi keyboard packs 10 keys across at ~27 px tall on a resistive panel — under the ~44 px comfortable target. Mis-taps are likely; enlarge keys or split the layout.
6
Strength · States
Thoughtful appliance states
On-screen keyboard + scan list for headless WiFi, signal bars, an epoch countdown with a distinct “ROLLING NOW” state, and an inline confirm row — these are real, considered touches, not an afterthought.

Where to spend the effort

Prioritized. The first item is the only one that touches identity; the rest are surgical UX fixes that keep the zero-dependency, single-file ethos intact.

PRIORITY 01
Own the brand
Replace the Miningcore-derived shield and palette with an original mark and color system. One change propagates to web, TFT and splash. This is the only real liability in the whole stack.
PRIORITY 02
Separate watch from configure
Web: tab or collapse the config forms so a glance never scrolls past the reboot button. TFT: lead with 2–3 vital stats, demote the rest to a detail screen.
PRIORITY 03
Make state legible
Tabular numerals on every live value, a “Saved — restarting” confirmation after each POST, and truncation/ellipsis on variable-length fields on the TFT.
PRIORITY 04
Loosen the density
More breathing room, larger type, fewer fields per view, and bigger keyboard targets for resistive touch. Comfort beats completeness on a 2.8″ panel.
KEEP DOING
The single-file, dependency-free architecture; the defensive stale/connected status model; one design language across both surfaces; and confirm-guards on destructive actions. These are the marks of a thoughtful engineer UI — the review above is polish on a solid base, not a teardown.
